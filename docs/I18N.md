# Internationalization checks

The repository's localization checks and catalogs have no Python runtime dependency. The diagnostic/UI catalogs remain under `locales/`; the existing validator and `npm run i18n-check` contracts are unchanged.

## GDScript literal analyzer

`npm run i18n-no-literals` scans `game/**/*.gd`, `game/**/*.tscn`, `game/**/*.{mjs,js,cjs}`, and `cli/**/*.{mjs,js,cjs}` when `cli/` exists. It checks non-empty display-property values, Godot output calls, and JavaScript CLI output. Translation/catalog calls and technical diagnostic identifiers remain allowed. Its output includes the scanned paths and file count.

The analyzer uses the real GDScript parser from **gdtoolkit 4.5.0**. The parser is installed only into the isolated `tools/i18n/.venv/`; it is not a `package.json` dependency and is not part of runtime core. The exact Python requirement is pinned in `tools/i18n/parser-requirements.txt`. The parser-backed pass validates each scanned `.gd` file and detects literal-bearing expressions, including multiline strings and constant `String.chr(...)` concatenations. The existing tokenizer remains a pre-filter/supplement; it cannot establish a clean result without the parser.

Set up or repair the isolated parser environment with:

```sh
node tools/i18n/setup-parser.mjs
```

Check availability without installing or changing anything with:

```sh
node tools/i18n/setup-parser.mjs --check
```

The default environment path is `tools/i18n/.venv/`. Set `SYNAPSE_I18N_VENV` to use another virtual-environment path. A missing or incorrect parser causes both the analyzer and `--check` to exit non-zero. They emit a JSON record with `event: "parser.unavailable"`, the selected environment path, and the recovery command; the analyzer never reports zero findings when parser availability is unknown. Parser setup is idempotent and can be repeated after the ignored `.venv/` is removed.

The i18n literal tests ensure the parser is set up before running their parser-dependent probes. The normal `i18n-check` command and its catalog coverage requirements are independent and unchanged.
