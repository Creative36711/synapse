# Локали и ключи каталога

Правило ядра: **пользовательский текст живёт только в каталогах перевода**. Контракт хранит ключи,
диагностика — код и параметры. Это не «перевод потом»: локаль — часть контракта с первого дня.

## Набор локалей

Восемь локалей, зафиксированных регламентом (§9):

| Локаль | Роль |
|---|---|
| `en` | по умолчанию и юридически аутентичная |
| `ru` | русский |
| `zh-Hans` | китайский (упрощённый) |
| `ja` | японский |
| `pt-BR` | португальский (Бразилия) |
| `de` | немецкий |
| `fr` | французский |
| `ko` | корейский |

Набор закрыт: значение вне списка — `field.enum` с `expected` = список локалей. Добавление локали —
изменение контракта, а не настройка игры.

## Где локали участвуют в контракте

| Место | Поле | Смысл |
|---|---|---|
| GameSpec | `locales.default`, `locales.supported` | какие локали игра объявляет и какая основная |
| Манифест модуля | `provides.locales` | какие локали поставляет модуль |
| GameSpec / манифест | `titleKey`, `descriptionKey` | ключи названия и описания |
| Манифест модуля | `conflicts[].reasonKey` | ключ причины конфликта |

Литерального текста в этих полях быть не может: `titleKey: "Сад"` — ошибка `field.pattern`, а не
«переведём позже».

## Ключи каталога

```
translationKey := segment ("." segment)+
segment        := [a-z][a-z0-9_]*
```

| Валидно | Невалидно | Причина |
|---|---|---|
| `game.example_minimal.title` | `Заголовок игры` | верхний регистр и пробелы |
| `module.synapse_core_ui.title` | `game..title` | пустой сегмент |
| `module.synapse_core_platformer.conflict.legacy` | `game.title ` | пробел в конце |

Ключ ошибки всегда выводится из кода: `catalogKey = "errors." + code`, например
`errors.locale.key.missing`. Отдельно придумывать ключ ошибки нельзя — иначе реестр и каталог
разъезжаются.

## Каталоги ядра и каталоги игры

Core-каталоги `locales/<locale>.json` в корне репозитория — авторитетный источник диагностических
текстов CLI и валидатора; игровые каталоги рядом с GameSpec не могут переопределять пространство
`errors`, потому что это пространство ядра. При совпадении ключа побеждает core-каталог, а сам
конфликт объявления — ошибка, а не повод для тихой подмены текста.

## Отсутствующий ключ

Если ключ не найден для требуемой локали (K-3):

```json
{
  "code": "locale.key.missing",
  "params": {
    "path": "/game/titleKey",
    "expected": "ключ game.example_minimal.title в каталоге локали de",
    "actual": "ключ отсутствует",
    "locale": "de",
    "catalog": "game"
  },
  "catalogKey": "errors.locale.key.missing"
}
```

Подставлять английский текст молча нельзя: игрок увидит смесь языков и решит, что перевод сломан.
Ошибка называет локаль и каталог, чтобы автор знал, что именно дописать.

## Что гарантирует контракт

- **INV-9.** Пользовательский текст — только из каталога. В схемах, реестре и коде нет строк,
  которые видит игрок.
- **INV-10.** Локаль не меняет смысл проверки и состояние мира: тот же файл даёт те же коды, пути и
  параметры при любой локали.
- Ключи обязаны существовать для всех восьми локалей; нативных ревьюеров нет, перевод и проверка —
  силами ИИ-агентов.

## Чего пока нет

Каталоги переводов введены карточкой K-6 (`locales/<locale>.json`, загрузчик и проверки —
`tools/i18n/**`, `tests/i18n/**`); K-2 фиксировал только требования к ключам, набор локалей и
диагностику отсутствующего ключа. Проверка существования ключей — семантика K-3, а не эта карточка.
