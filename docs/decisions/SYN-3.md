# SYN-3 · B1 · Отпечаток мира v2 и таблица ошибок сцены

- **Дата:** 2026-11-02
- **Область записи:** `schema/**`, `docs/contracts/**`, `tests/contracts/**`, этот файл
- **Основание:** D-058 (отпечаток из двух объявленных срезов), инварианты INV-12 и INV-15

Статус: accepted

## Что решено и зачем

Отпечаток v1 (`synapse.world-state.v1`) содержит только сцену, дерево узлов и свойства
узлов: ни локали, ни текста, ни кадра. Значит, два документа, снятые в разных локалях,
совпадают по построению, и их равенство не доказывает ничего — оно проходит и на полностью
непереведённом интерфейсе, и на переводе, который поехал в геометрию (F-1). Публичный
контракт ошибок сцены при этом не описывал двух кодов, видимых ровно на пути «сцена из
модуля»: `ref.unresolved` и `actions.file.missing` (F-7).

Решено:

1. Ввести `synapse.world-state.v2` из двух объявленных срезов и `artifact` (D-058):
   * `rules` — кадр, геометрия, видимость, состояние сущностей; **без** локали и текста;
   * `presentation` — локаль и переводимые поля `text`, `tooltip_text`, `title`;
   * `artifact` — полный хеш документа без самого `artifact`, только идентичность;
   * `fingerprintScope` — имена срезов, перечень полей каждого среза и правило сравнения
     `within-version-by-slice`.
2. Заморозить v1: восстановить его схему по текущему эмиттеру (`game/cli/main.gd`) и
   закрепить документом, снятым этим эмиттером. Формат v1 не меняется, документы SYN-1/SYN-2
   остаются валидными.
3. Дописать `docs/contracts/world-state.md`: порядок нормализации, правило хеша, правило
   сравнения и две негативные фикстуры.
4. Зарегистрировать наборы `world-state-v1` и `world-state-v2` в `CASE_SETS` (жёсткий массив,
   автообнаружения нет) и добавить таблице `docs/contracts/scene-binding.md` строки
   `ref.unresolved` и `actions.file.missing`.

Код не писался: ни эмиттер, ни рантайм, ни валидатор. `game/**` не тронут. Расхождение V-4
(эмиттер пока не пишет `frame`, `presentation`, `fingerprintScope`) вынесено на B4 —
контракт фиксирует форму и правило сравнения заранее.

## Решения по формату: неясно / решил / откат

| Неясно | Решил | Откат |
|---|---|---|
| Как различить «правила» и «представление», чтобы перевод не прятался за общий хеш | два отдельных среза с собственными хешами: `rules` и `presentation`. Один общий хеш отвергнут: он не даёт ответить ни на INV-12, ни на INV-15 | убрать `presentation` из документа и оставить один срез; INV-15 при этом нечем доказать — это ухудшение, не рекомендуется |
| Где живёт локаль | в `presentation.locale`, а не в корне и не в `rules`: локаль — свойство представления, и её присутствие в `rules` сделало бы INV-12 невыполнимым по построению | перенести `locale` в корень документа и исключить её из сравнения срезов; правило сравнения станет сложнее |
| Что делать с полным хешем: убрать или оставить | оставить как `artifact` с явной оговоркой «только идентичность, в INV-12 не участвует». Он меняется от любой смены локали, поэтому его равенство не критерий ничего | удалить `artifact`; тогда нечем пометить конкретный документ прогона |
| Нужен ли `fingerprintScope` в документе | да: имена срезов + перечень полей + константа правила. Без него состав отпечатка приходится угадывать по коду, а «срез» превращается в устное соглашение | оставить перечень полей только в документе `world-state.md`, убрать из схемы; проверка «объявленное = фактическое» станет невозможной |
| Как записать перечень полей, чтобы он не отставал от схемы | закрытый enum в схеме (`rulesNodes[].properties.*`) плюс тест, сверяющий `fingerprintScope.fields` с фактическим набором `$defs.rulesProperties`/`presentationProperties` | разрешить свободные строки; тогда перечень полей молча разойдётся со схемой |
| Кадр: включать ли в отпечаток | да, `rules.frame`. Без него «одинаково» не отличить от «снято в разные моменты». В v1 кадра не было | убрать `frame`; различие по времени придётся ловить снаружи, а сравнение станет недостоверным |
| Чем нормировать числа, чтобы хеш не дрожал от float | округление до 4 знаков после запятой, `-0` → `0`, без экспоненты. Явный допуск: разница меньше `1e-4` пикселя изменением правил не считается | сравнивать сырые float — хеш станет нестабильным между платформами; или поднять точность до 6 знаков, если экранной точности не хватит |
| Как быть, если `presentation` описывает узел, которого нет в `rules` | запретить: `path` обязан указывать на существующий узел, узел без переводимых полей в срез не попадает (пустой `properties` запрещён схемой) | разрешить «висячие» записи и чистить их сравнением; тогда ошибка раскладки станет невидимой |
| Сколько примеров нужно и какие из них обязаны быть «сломанными» | две негативные фикстуры, обе **валидны по схеме**: (а) геометрия зависит от локали → `rules` различаются; (б) перевод → `presentation` различается, `rules` равен. Схема такие документы пропускает — ловит правило сравнения | оставить только «красивые» примеры; тогда ни INV-12, ни INV-15 ничем не подтверждены |
| Чем проверять хеши в примерах | не выписывать руками: тест пересчитывает канонический JSON по документу. Ручные хеши устаревают молча | вернуть статические хеши и проверять только форму; подмена полей перестанет обнаруживаться |
| Регистрировать ли `scene-binding` в `CASE_SETS`, раз таблицу ошибок правим | нет. Набор намеренно вне `CASE_SETS`: его кейсы — эталон для семантического валидатора K-3, а не пройденная проверка. Регистрация была бы расширением оракула, а не его усилением | зарегистрировать `scene-binding` и реализовать семантические шаги — отдельная карточка, меняющая оракул, а не эта |
| Откуда два кода для таблицы ошибок сцены | из реестра `schema/error-registry.json`: `ref.unresolved` (resolution, K-4, extraParams `refKind`, `providedBy`) и `actions.file.missing` (semantic, K-3, extraParams `file`). Таблица в `errors.md` их уже содержала, `scene-binding.md` — нет | убрать строки из `scene-binding.md`; тогда путь «сцена из модуля» описан не полностью, F-7 остаётся |
| Как связать v1-схему с кодом, чтобы она не стала пожеланием | положить в примеры документ, снятый текущим эмиттером байт в байт, и требовать его валидности тестом | оставить только рукописный пример; схема начнёт описывать воображаемый формат |

## Что изменено в проверках

`npm run check:contracts`: было **99** тестов, стало больше за счёт двух наборов кейсов
(`world-state-v1`, `world-state-v2`) и нового файла `tests/contracts/world-state.test.mjs`.
Проверки не ослаблялись: `scene-binding` не зарегистрирован, `--frames 0` не использовался,
существующие кейсы и схемы не правились (правка `CASE_SETS` — только добавление двух имён).
