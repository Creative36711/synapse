## Контекст

K-2 фиксирует контракты до реализации валидатора (K-3) и резолвера (K-4). Контракт читают:

- автор игры — глазами, в редакторе, без нашего кода;
- валидатор K-3 — машинно, по схеме;
- резолвер K-4 — машинно, по графу модулей;
- ревьюер и аудитор — в диффе PR.

Из этого следуют требования, которые и определили выбор:

1. Описание игры должно быть читаемым и комментируемым — это авторский артефакт, а не конфиг сервиса.
2. Структурная проверка должна быть стандартной и не требовать самописного парсера схем.
3. Диагностика должна быть машинной и переводимой: `code` + `params`, текст — из каталога (INV-6,
   INV-9).
4. Проверка обязана работать офлайн, без cortex, аккаунта и секретов (INV-1).
5. Логика адресуется смысловыми ID, а не путями ассетов (INV-3).

## Решение (черновик, действует до ответа)

1. **Формат описаний — YAML 1.2 (core schema).** Комментарии, минимум пунктуации, построчный дифф,
   надмножество JSON.
2. **Правила чтения — часть контракта:** повтор ключа и merge-ключ `<<` запрещены, теги не
   исполняются, даты и `yes/no` не преобразуются неявно.
3. **Структурные схемы — JSON Schema 2020-12** с `additionalProperties: false` и локальными `$ref`
   в `$defs`. `$id` — в зоне `.invalid`, внешних ссылок нет: сеть не нужна.
4. **Ошибка — `code` + `params(path, expected, actual)`**; `catalogKey` строго `errors.<code>`.
   Текста ошибки в реестре нет.
5. **Реестр ошибок — JSON**, потому что это машинный артефакт с собственной схемой, а не авторский
   текст.
6. **Каждый контракт имеет пример «валидно» и «невалидно»**, привязанный к коду и пути в
   `cases.json`; проверка сверяет их и падает при расхождении.

## Варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| **A. YAML + JSON Schema 2020-12 + `code`/`params`** (по умолчанию) | читаемо автором, схемы стандартные, дифф чистый, JSON-проекция бесплатна | нужны строгие правила чтения YAML (повторы, теги) | действует как черновик |
| B. Только JSON | один формат для людей и машин, нет вопросов к YAML | нет комментариев, шумная пунктуация, авторские правки тяжело ревьюить | не выбран |
| C. Свой текстовый формат / TOML | полный контроль | самописный парсер и самописная схема, экосистема инструментов нулевая | не выбран |

Отклонение варианта A не меняет грамматики полей, коды ошибок и `params`: при смене формата
переписывается сериализация и примеры, а смысл контракта остаётся.

## Последствия

- Появляется одна команда проверки — `npm run check:contracts`, офлайн, без сервисов.
- Контракт нельзя «расширить на месте»: лишнее поле — ошибка, а не молчание.
- Автор обязан писать ключи каталога вместо текста; это дороже на старте и дешевле при восьми локалях.
- Появляются devDependencies (`ajv`, `yaml`) — только для проверки, не для рантайма.
- Ошибки становятся машинными: UI собирает фразу из каталога, а не печатает строку из кода.

## Обратимые решения (неясно / решил / откат)

| Неясно | Решил | Откат |
|---|---|---|
| Где держать контрактные примеры: `docs/contracts/examples/**` или `schema/examples/**` | `schema/examples/**` — примеры рядом со схемами, которую они проверяют | перенести каталог и поправить `cases.json` (пути в них относительные) |
| Где держать скрипт проверки: `scripts/` или `tests/contracts/` | `tests/contracts/check-contracts.mjs` — Scope карточки разрешает `tests/contracts/**` и не разрешает `scripts/**` | перенести файл и строку `scripts.check:contracts` в `package.json` |
| Имя файла записи решения | `docs/decisions/SYN-1.md` — так назван путь в Scope карточки | переименовать файл; тест ищет статус в этом пути |
| Нужна ли строка `node_modules/` в `.gitignore` | добавил: без неё `git add -A` затянет зависимости в коммит | удалить строку, если ревью сочтёт её выходом за Scope |
| Формат реестра ошибок: YAML или JSON | JSON — машинный артефакт, проверяется своей схемой, автор его не редактирует | перевести в YAML и читать тем же строгим загрузчиком |
| Минимальная версия Node | `>=20.19.0` (в песочнице 22.22.3, `node --test` и ESM без флагов) | поднять порог в `engines`, ничего больше не меняя |
| Лицензионный файл в корне репозитория | не создавал: вне Scope карточки; `package.json` помечен `MIT` (INV-8) | отдельная карточка добавляет `LICENSE`, поле `license` не меняется |
